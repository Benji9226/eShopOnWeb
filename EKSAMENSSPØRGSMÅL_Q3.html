Intro & mål

Forklar kort: hvorfor teststrategier og message transformations er vigtige i et distribueret system.

Speaker notes (1 min):
  • Sig hvem du er og formålet: sikre data‑og kontrakt‑integritet i microservices.
  • Giv ét konkret problem: producer og consumer har forskelligt schema → transformation nødvendig.

Testtyper — kort (Unit / Integration / E2E)

  • Unit: test små rene funktioner (fx mapping)
  • Integration: test mod database eller broker (ephemeral)
  • E2E: test hele flowet (API -> broker -> consumer -> DB)
Speaker notes (2 min):
  • Forklar kort formål og eksempler: transformationsfunktioner som unit tests.
  • Integration: brug docker/testcontainers (repo har eksempler i MicroServices/CatalogMicroService/tests).

Struktur og repo-praksis

  • Hver service ejer sine tests (unit + integration)
  • CI kører integration tests i containeriseret miljø
Speaker notes (2 min):
  • Vis konkrete filer: MicroServices/CatalogMicroService/tests/conftest.py (pytest fixtures), .github/workflows/build-and-test.yml (CI job).
  • Siger: "Når I skriver transformer-funktioner, placér unit tests ved siden af modulet — integration tests i tests-folder."

Hvad er Message Transformation?

Kort: ændring af payload så producenter og forbrugere kan forstå hinanden.

  • Konvertering af feltnavne
  • Schema-opgradering (v1 → v2)
  • Berigelse / fjernelse af interne felter
Speaker notes (3 min):
  • Giv konkret eksempel fra repo: producer af order event (se src/Infrastructure/RabbitMQ/RabbitMqService.cs for patterns) og hvordan en transformer fjerner interne felter før consumer.
  • Forklar trade-offs: producer-side vs middleware vs consumer-side transformation.

Teststrategier for messaging

  • Unit: test mapping/transform funktioner (hurtige)
  • Integration: ephemeral RabbitMQ + test flow
  • Contract tests: Pact eller schema registry
  • E2E: valider end-state i DB
Speaker notes (3 min):
  • Walkthrough: hvordan skrive en integrationstest der starter en rabbitmq-container (brug docker compose eller Testcontainers).
  • Referér til repo: kig i MicroServices/CatalogMicroService/tests for fixtures; i .NET delen kan src/Infrastructure/RabbitMQ/RabbitMqService.cs illustrere publicering.

Konkrekt test-eksempel (walkthrough)

# pseudo pytest
def test_order_event_transformation(rabbitmq_container):
    # arrange: publish v1
    publish(queue='orders.in', body=ORDER_V1_JSON)

    # act: consumer receives transformed v2
    msg = consume(queue='orders.out', timeout=5)

    # assert: check transformation
    assert msg['amount'] == 1000
    assert 'internal_flag' not in msg
    assert msg['schema_version'] == 'v2'
Speaker notes (3 min):
  • Gennemgå arrange/act/assert kort — fremhæv hvorfor ephemeral broker er bedst for integrationstests.
  • Praktisk tip: seed test data i fixtures (se conftest.py) og ryd op efter test.

CI & automation

Hvordan køre tests automatisk i CI:

  • Split jobs: unit (hurtige) / integration (containers) / e2e (trimmed env)
  • Gem artefakter (logs, messages) ved fejl
Speaker notes (2 min):
  • Vis linjer fra .github/workflows/build-and-test.yml hvor integration tests køres.
  • Tip: Kør langsomme e2e nattetimer eller som gating for release branches.

Opsummering — korte takeaways

  • Skriv transformationslogik som rene funktioner — nemt at unit-teste
  • Brug ephemeral brokers for integrationstests
  • Automatiser i CI og del kontrakt-tests mellem teams
Speaker notes (1 min):
  • Gentag mål og opfordr til spørgsmål.
  • Tilbyd at vise eksempelkode i repoet efter præsentation.
